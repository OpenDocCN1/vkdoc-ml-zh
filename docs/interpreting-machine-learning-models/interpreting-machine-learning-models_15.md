# 15. 可解释性方法的八大陷阱

与模型无关的模型解释技术，例如排列重要性图、排列特征重要性和沙普利值，为模型解释提供了许多见解，但如果使用不当，常常会导致错误的结论。

本章重点介绍模型解释中的许多常见陷阱，例如在错误的上下文中使用解释技术，或使用泛化能力不佳的模型。有时，人们会忽略高维数据集中的特征依赖性、交互作用和不确定性估计。本章将重点介绍在使用可解释性技术时可能出现的常见陷阱。

由于许多可解释性技术都基于操纵数据和探索模型这一相同原理，因此它们也共享许多缺点。大多数模型通常具有非线性效应和高阶交互作用。无论模型在测试数据上的性能如何，都可以应用解释方法，但只有当模型泛化良好时，我们才能对数据得出可靠的结论。在某些情况下，一个更简单的模型就足以完成所需任务，因此，复杂的模型和模型可解释性技术可能会增加不必要的复杂性。像这样的缺点很容易被忽视，但它们在许多机器学习实践中却相当常见。

## 假设存在“万能”的可解释性

从业者可以选择很多可解释性方法来回答模型为何做出特定决策的问题。过多的选择使得从业者难以根据自身需求选择合适的方法。认为单一的可解释性方法可以适用于多种用例，这是一个非常危险的假设。例如，有许多全局特征重要性方法，如排列特征重要性和 SHAP。两者提供的输出可能完全不同，其使用目标也可能不同。例如，如果模型构建者希望了解特征（例如，数据科学家选择模型特征）与模型泛化误差的相关性，则应使用基于损失的方法，如排列特征重要性。当模型构建者希望揭示模型进行预测所依赖的特征时（例如，业务分析师分析模型以向利益相关者展示），则应使用 Shap 特征重要性。因此，模型构建者必须仔细研究他们对可解释性方法的选择，以确保其与目标一致，并产生有意义的分析。

## 模型泛化能力差

当模型欠拟合或过拟合时，可能会导致误导性的特征重要性得分，因为输出与底层模型的匹配度不够好。

大多数可解释性方法旨在解释模型，而不是对数据生成过程进行推断。当模型能够很好地近似数据生成过程时，对其的解释才能揭示对底层过程的见解。永远不应使用训练数据来评估模型性能，因为这样模型可能会过拟合训练数据，导致乐观或膨胀的估计。应使用基于采样过程的样本外验证，因为许多此类方法易于获得、研究充分且实践成熟。在计算模型选择和超参数调优中，首选嵌套采样。

## 不必要地使用复杂模型

使用可解释性技术时的一个常见陷阱是，在简单的自解释模型就足够的情况下，却使用了不透明的复杂模型。尽管与模型无关的可解释性技术为复杂黑箱模型的行为和机制提供了很多启示，但有时可解释模型提供了高度的透明度。

虽然与模型无关的方法可以揭示复杂机器学习模型的行为，但本质上可解释的模型仍然提供更高程度的透明度，并且考虑它们会增加发现真实数据生成函数的可能性。人们普遍认为，复杂的机器学习模型在准确性方面总是优于更可解释的模型，因此应该优先选择。然而，有多个例子证明，可解释模型是强有力的竞争者。

我们建议从简单的、可解释的模型开始，例如线性回归模型和决策树。GAM（广义加性模型）可以在简单的线性模型和更复杂的机器学习模型之间逐步过渡。GAM 具有一个理想的特性，即可以加性地建模平滑的非线性效应，并开箱即用地提供部分依赖图（PDP），同时避免了掩盖交互作用的潜在陷阱。GAM 的加性模型结构在拟合模型之前就已指定，因此只估计预先指定的特征或交互效应。特征之间的交互作用可以手动或通过算法（例如，通过前向贪婪搜索）添加。

只有当准确性的提升显著且相关时，才应优先选择复杂模型。然而，强烈建议从简单模型开始，然后逐步尝试更复杂的模型。

## 忽略特征依赖性

在应用解释方法之前，从业者应检查数据中特征之间的依赖性。让我们看看特征依赖性可能引起的各种问题。

### 外推解释

每当机器学习模型依赖于特征交互（即特征相互依赖）时，那些在训练数据中进行外推的方法，如排列特征重要性、部分依赖图和沙普利值，常常会导致误导性的解释。这些外推或扰动会产生用于模型预测的人工数据点，并进一步聚合以生成全局解释。特征值通常通过随机子采样值进行扰动。

因此，无论何时应用模型解释方法，都应始终通过描述性统计或依赖性度量来检查特征之间的依赖性。如果在模型中包含了依赖特征，还应提供关于依赖强度和关系类型的额外信息。

### 混淆线性相关与一般依赖

有时，当特征之间的相关系数为零时，特征之间仍然可能存在依赖关系，并且当将其放入模型时，可能会导致误导性的模型解释。“特征之间的独立性意味着皮尔逊相关系数为零”的逆命题通常是不成立的。该系数通常追踪线性关系，并且经常受到异常值的影响。

当特征数量较少时，我们可以使用散点图。然而，对于高维图，我们可以使用其他依赖性度量。如果依赖关系是单调的，则可以使用斯皮尔曼秩相关系数。对于分类或混合特征，我们应该使用单独的度量方法。



### 误解条件性解释

解释技术的条件性变体避免了外推，但需要不同的解释。那些独立于其他特征扰动特征的解释方法，在特征存在依赖关系时会进行外推，但能提供对模型机制的洞察。解释技术的条件性变体避免了外推，但需要不同的解释。因此，这些方法被认为对模型忠实，但对数据不忠实。对于诸如部分依赖图之类的特征效应方法，该图可被解释为该特征对预测的、孤立的平均效应。对于排列特征重要性，其重要性可被解释为当特征信息被“破坏”（通过扰动它）时性能的下降。当特征高度依赖，并且使用条件效应和重要性分数时，实践者必须意识到这种独特的解释。

## 由特征交互导致的误导性解释

有时，当使用各种方法生成解释时，特征交互会导致大量混淆。让我们探讨特征交互可能引起的各种问题。

### 由聚合导致的误导性特征效应

全局解释方法，例如部分依赖图或累积局部效应图，可视化了对模型预测的平均效应。然而，当特征交互时，它们可能会产生误导性的解释。

对于部分依赖图，我们建议额外考虑相应的个体条件期望曲线。ICE 曲线直接显示了个体预测之间的异质性，而部分依赖图和累积局部效应则平均了交互效应。将这些个体条件期望曲线聚合为全局边际效应曲线（如部分依赖图）并不会丢失太多信息。然而，当特征交互时，不同观测值的边际效应曲线可能不会显示出对目标变量的相似效应。

### 未能分离主效应与交互效应

对于模型解释方法来说，将交互效应与主效应分离开来非常重要。例如，排列特征重要性既包含了特征的重要性，也包含了与其他特征的交互作用。像 SHAP 和 LIME 这样的方法提供了加性解释，但没有分离主效应和交互效应。功能 ANOVA 可能是将联合分布分解为主效应和交互效应最流行的方法。使用相同的思路，H 统计量通过将二维 PDP 分解为单变量分量，来量化两个特征之间或一个特征与所有其他特征之间的交互强度。在无交互的特征中，二维部分依赖函数等于两个底层单变量部分依赖函数之和。

## 忽略模型与近似不确定性

许多解释方法只提供均值估计，而不量化不确定性。模型训练和解释的计算都存在不确定性。模型是在（随机）数据上训练的，因此应被视为一个随机变量。解释方法通常根据对数据的期望来定义（PFI、PDP、Shapley 值等），但使用蒙特卡洛积分进行近似。忽略这两个不确定性来源可能导致对噪声的解释和非稳健的结果。这种效应在多次模型拟合后取平均可能会抵消。单个 PDP 可能具有误导性，因为它没有显示由 PDP 估计（第二张图）和模型拟合引起的方差。如果我们不关心了解特定模型，而是关心特征 X1 与目标变量之间的关系，我们应该考虑模型方差。

通过使用给定模型但采用不同排列或 bootstrap 样本重复计算 PDP 和 PFI，可以量化估计的不确定性，例如以置信区间的形式。对于 PFI，存在置信区间和假设检验的框架，但它们假设模型是固定的。如果实践者希望以建模过程为条件进行分析，并捕获该过程的方差，而不是以固定模型为条件，则应在多个模型拟合上计算 PDP 和 PFI。

## 未能扩展到高维设置

有时，在生成或使用解释时会忽略高维设置。让我们探讨这可能导致的问题。

### 高维 IML 输出的人类可理解性

将可解释性方法天真地应用于高维数据集（例如，在特征层面可视化特征效应或计算重要性分数）会导致产生大量且高维的可解释性输出，这阻碍了人类分析。特别是基于可视化的解释方法，使得实践者在高维设置中难以聚焦于最重要的洞察。

一种自然的方法是在应用任何 IML 方法之前降低维度。这是否有助于理解，取决于所得到的降维特征空间可能具有的语义可解释性，因为特征可以被选择，或者维度可以通过线性或非线性变换来降低。如果用户希望在原始特征空间中进行解释，可以使用许多特征选择技术，从而得到更稀疏、更易于解释的模型。包装器选择方法是模型无关的，像贪婪前向选择或子集选择程序这样的算法，从空模型开始，根据需要迭代地添加相关的（子集）特征，甚至允许衡量特征对预测性能的相关性。另一种方法是直接使用隐式执行特征选择的模型，例如 LASSO 或分量提升，因为它们可以产生具有更少特征的稀疏模型。

### 计算开销

一些解释方法不会随特征数量线性扩展。例如，对于精确 Shapley 值的计算，可能的联盟数量，或者对于（完整的）功能 ANOVA 分解，其分量数量（主效应加上所有交互作用）的规模是 O(2^p)。

对于功能 ANOVA，一个常见的解决方案是将分析限制在主效应和选定的双向交互作用上（类似于 PDP 和 ALE）。可以通过另一种方法（如 H 统计量）来选择有趣的双向交互作用。然而，选择双向交互作用需要额外的计算开销。交互强度通常随着交互规模的增加而迅速下降，并且只有当所有(d-1)阶交互作用都显著时，才应考虑 d 阶交互作用。对于基于 Shapley 的方法，存在一种基于随机采样和评估特征排序直到估计收敛的高效近似方法。估计的方差以 O(1/m)的速度减少，其中 m 是评估的排序数量。



## 不合理的因果解释

技术数据科学专家通常对数据生成机制背后的因果洞见感兴趣，而模型可解释性方法通常无法提供这类洞见。常见的因果问题包括识别因果关系、预测干预效果以及回答反事实问题。例如，医学研究人员可能希望识别风险因素，或预测平均及个体治疗效果。因此，研究人员很容易试图从因果角度解释可解释性方法的结果。然而，对预测模型进行因果解释往往是不可能的。标准的监督式机器学习模型并非为建模因果关系而设计，而仅仅是利用变量间的关联性。模型可能依赖于目标变量的原因和结果，以及重构对 Y 的未观测影响（例如结果的原因）的变量。因此，某个变量是否与预测模型相关（例如通过 PFI > 0 来指示），并不能直接表明该变量是原因、结果，还是与目标变量不存在任何因果关系。

## 总结

本章回顾了解释技术中的众多陷阱，例如模型泛化能力差、特征依赖、特征间的交互作用或因果解释问题。我们希望鼓励在实践中对机器学习模型进行解释时采取更谨慎的态度，并向实践者指出已有的（部分）解决方案。风险很高：机器学习算法越来越多地被用于与社会相关的决策，而模型解释在这些决策中扮演着重要角色。因此，我们相信，关于 IML 技术的特性、危险和问题的具体指导将使您受益。我们需要努力朝着一个推荐且被充分理解的工具集迈进，而这需要更深入细致的研究。

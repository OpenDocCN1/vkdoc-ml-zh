# 第 9 章 结论

你读完了这本书——恭喜！这是一段漫长的旅程，我希望它也是一段愉快的旅程——一段让你在途中收获一两个想法的旅程。在我们分别之前，我认为回顾一下我们共同取得的成就或许是值得的，也许还能看看是否存在一些跨越各章节的、更广泛的主题，尽管它们之间差异巨大。

绘制我们的旅程

我写这本书的目标是，以一种对 .NET 开发者来说既易于理解又有趣的方式，介绍机器学习这一主题。机器学习是一个庞大的主题，它理所当然地每天吸引着越来越多的关注。同时，这个主题也常常以某种抽象的方式呈现，导致许多人认为它是一个复杂的话题，最好留给数学家去处理。

虽然数学在机器学习中扮演着重要角色，但我希望，在阅读本书后，你能意识到它并不像听起来那么复杂，而且许多核心思想实际上相当简单，并适用于广泛的实际问题。

让我们退后一步，看看我们覆盖了哪些领域。在非常高的层面上，我们建立了一张类似机器学习问题地图的东西，并做出了重要的区分。首先，我们介绍了监督方法和无监督方法。每种方法解决一个不同的问题，如下所示：

*   **无监督方法**旨在帮助你理解数据，当你还不知道自己可能想探究什么问题的时候。这是第 5 章的主要主题，我们获取了一个 StackOverflow 问题的数据集，并简单地寻找模式，以帮助我们理解原本难以解释的非结构化数据。
*   相比之下，**监督方法**（我们花费了大部分精力，见第 1 章、第 2 章、第 4 章和第 6 章）则是基于带标签的示例（即已知正确答案的数据）来训练模型，以回答一个对我们至关重要的、定义明确的问题。

在探索过程中，我们涵盖了多种模型，它们之间存在重要差异。首先，我们区分了分类模型和回归模型，它们的区别在于我们期望从它们那里得到的答案类型。**回归**模型旨在预测一个连续的数值；在第 4 章中，我们开发了这样一个模型，根据各种输入来预测自行车共享服务的使用水平。相比之下，**分类**模型则是在有限数量的可能结果中，判断哪一个最有可能。我们看到了这类模型的三个例子，从自动识别图像代表十个可能数字中的哪一个（第 1 章），到区分正常邮件和垃圾邮件（第 2 章），再到预测泰坦尼克号上哪些乘客能够幸存（第 6 章）。

我们还在第 7 章中探索了一种使用强化学习的不同方法。由此产生的模型是一个分类器，它在有限的一组可能动作中做出决策，与之前的模型有一个关键区别：我们不是一次性利用过去的数据进行学习，而是构建了一个模型，该模型随着新观测值的不断涌入而持续学习，这种方法通常被称为**在线学习**。



在整本书中，我们深入研究了各种真实数据集，并让数据引导我们的探索。尽管主题看似多样（图像、文本、数字等），但不同问题之间仍浮现出一些模式。在大多数情况下，我们最终都应用了**特征提取**——将原始数据转换为更具信息性或更便于处理的值行。而且，正如我们在模型中寻找的答案类型决定了分类或回归哪个更合适一样，根据特征是连续型还是类别型，我们最终采用了不同的方法。我们还看到，如何通过分箱（例如泰坦尼克号示例中的年龄）将连续特征转换为离散特征，或者反过来，如何将类别特征展平为一系列指示变量（例如回归示例中的星期几）。

科学！

我们在各章节中看到的另一个模式涉及方法论。我们从想要回答的问题开始，收集所有可用的数据，然后开始进行一系列实验，逐步创建并完善一个与事实相符的模型。

从这个意义上说，开发机器学习模型与开发常规业务应用程序有很大不同。当你构建一个应用程序时，通常有一组要实现的功能；每个功能都有某种形式的验收标准，描述完成它需要满足的条件。开发者将问题分解成更小的代码片段，将它们组合在一起，一旦所有部分按预期协同工作，任务就完成了。

相比之下，开发机器学习程序更接近于遵循科学方法的研究活动。你事先不知道某个特定想法是否可行。你必须提出一个理论，利用手头的数据构建一个预测模型，然后验证你构建的模型是否与数据吻合。这有点棘手，因为它使得估算开发这样一个模型需要多长时间变得困难。你可能尝试一个非常简单的想法，半天内就完成，也可能花费数周时间，除了失败的实验之外一无所获。

当然，事情并非完全如此泾渭分明。开发常规应用程序时也存在一些不确定性，也会有一些失败的实验。然而，事实仍然是，在机器学习中，除非你将模型与数据对照，否则你不会知道你的想法是否可行。话虽如此，一些软件工程的思想仍然适用，尽管方式略有调整。

正如明确说明你要交付的功能的规范会有所帮助一样，尽早思考如何衡量成功，并为此设定目标也至关重要。正确的代码只是构成一个好的机器学习模型的一小部分；要具有价值，模型必须有用，这意味着它必须擅长做出预测。在这个框架下，我们在整本书中反复使用了**交叉验证**。将部分数据放在一边，不用于训练，一旦模型准备就绪，就在验证集上测试其效果，这模拟了模型在真实条件下看到新输入时可能发生的情况。在某些方面，交叉验证的作用类似于常规代码的测试套件，允许你检查事物是否按预期工作。

对我个人而言，无论是在机器学习还是软件开发中，一个行之有效的习惯就是尽快构建一个可工作的原型。在机器学习的背景下，这意味着创建你能想到的最简单、执行最快的模型。这有很多好处：它迫使你构建一个从数据到验证的端到端流程，你可以随着进展重复使用和完善它。它有助于及早发现潜在问题。它建立了一个基线，一个设定标准的数据，用以判断其他模型是好是坏。最后，如果你运气好，这个简单的模型可能效果就很好，这样你就能提前完成工作。

说到简单模型，有一点我真心希望在这本书中传达清楚了。围绕机器学习的许多讨论都强调花哨的模型和技术。复杂的算法很有趣，但归根结底，花时间理解数据和提取正确的特征通常要重要得多。将糟糕的数据输入复杂的算法并不会神奇地产生好的答案。相反，正如我们在几个章节中看到的，使用精心设计的特征的非常简单的模型可以产生出奇好的结果。而且，作为额外的好处，更简单的模型也更容易理解。

F#：以函数式风格高效工作

我们共同编写的大部分代码都是用 F# 编写的，这是一种以函数式优先的 .NET 语言。如果这是你第一次接触 F#，我希望你喜欢它，并且它能激励你进一步探索！在某种程度上，函数式编程面临着与机器学习类似的问题；也就是说，它常常被描述为一个理论性和抽象性的话题。过去几年 F# 成为我的主要语言的原因与理论无关。我发现它是一种效率极高的语言。我可以用清晰简单的代码表达想法，并快速完善它们，更快地完成任务。另外，我就是觉得用这种语言工作很有趣。

在我看来，F# 的优势在应用于机器学习主题时尤为突出。首先，内置的脚本环境以及语法轻量且富有表现力的语言至关重要。开发机器学习模型涉及大量的探索和实验，能够一次加载数据并在全天持续探索，而无需因重新加载和重新编译而中断思路，这是关键。

然后，如果你回顾一下我们共同构建的模型，你可能会注意到一个通用模式。从一个数据源开始，我们读取它并提取特征，应用一个学习过程来更新模型，直到拟合效果足够好，然后通过交叉验证计算一些质量指标。这个通用过程与函数式风格非常契合，并且我们的实现在不同问题中看起来相当相似：应用映射将数据转换为特征，使用递归来应用模型更新和学习，并使用平均值或折叠将预测结果缩减为准确率等质量指标。函数式语言的词汇与机器学习所追求的问题类型非常自然地契合。而且，作为额外的好处，强调不可变数据的函数式模式往往相当容易并行化，这在处理大量数据时会派上用场。



虽然这一点也适用于其他函数式语言，但 F# 具有一些使其特别引人注目的特性。第一个特性是类型提供程序，这是我们在第 3 章中探讨过的一种机制。大多数语言要么是动态类型，要么是静态类型，每种类型都有其优势或挑战。要么外部数据易于访问，但我们从编译器获得的帮助有限，要么情况正好相反。F# 类型提供程序解决了这一矛盾，使得数据（或语言，如我们调用 R 语言的示例）能够以极低的摩擦被使用，并以安全的方式被发现，同时兼具静态类型的所有优势。

F# 在该特定领域的另一个显著优势是它既能用于探索，也能用于生产。在本书中，我们主要关注第一个方面，在快速反馈循环中探索数据，并逐步优化模型。然而，一旦想法趋于稳定，将代码从脚本提升为模块或类，并将其转变为成熟的库是相当简单的，正如在几个章节中所展示的那样。你可以期待与 .NET 整体相同的性能水平——也就是说，相当不错。而且，此时你可以直接在生产环境中运行该代码，并将其与 .NET 代码库集成，无论该代码是用 C#、VB.NET 还是 F# 编写的。能够使用同一种语言从探索阶段过渡到生产阶段，具有真正的价值。我在许多地方看到过这样的开发流程：研究团队使用一套工具和语言创建模型，然后将其移交给开发团队，而开发团队要么选择重写所有代码（随之而来的是所有问题），要么尽力将外来工具集成并运行到生产系统中。F# 可以为这一矛盾提供一个有趣的解决方案，并且既可以作为研究人员的探索性语言，也可以作为开发人员的生产就绪语言。

接下来呢？

那么，你现在是机器学习专家了吗？如果这让你感到失望，我很抱歉，但这本书只是浅尝辄止，还有更多、更多的东西需要学习。话虽如此，如果你喜欢这个话题，好消息是你不会缺少有趣的学习材料（作为起点，我建议你看看 Coursera 上 Andrew Ng 的课程，并尝试一些 Kaggle 竞赛）。机器学习正在快速发展，这也是我非常喜欢这个领域的原因之一。

也许更重要的是，你可能还不是专家——但话说回来，由于这个主题的庞大性，很少有人是专家。然而，在这一点上，你很可能比大多数软件工程师更了解这个主题，并且你应该能够开始在你自己的项目中富有成效地使用我们一起讨论过的一些想法。最重要的是，我希望我已经成功地说服了你，机器学习既没有它最初看起来那么复杂，充满了对数学家和软件工程师来说都非常有趣的问题，而且非常有趣。所以，去尝试一下吧，做出伟大的事情，并享受其中的乐趣！

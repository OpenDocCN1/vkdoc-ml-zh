# 4. 使用 OBIEE 进行机器学习

从商业智能和分析的早期开始，人们就对这类解决方案能为决策者提供什么做出了许多承诺。由于近年来开发的新技术，随着更多功能的出现，商业智能和分析再次获得了大量关注，这些功能似乎终于兑现了承诺。

## 人工智能与商业智能的联姻

世纪之交，计算技术的进步为数据仓库开辟了一个全新的世界。当时，推动后来被称为商业智能与分析的发展成为首要任务。这是那些希望有效利用企业数据以获取某种竞争优势并影响公司利润的组织的主要关注点。如今，几乎所有组织都在使用某种形式的商业智能与分析，并在过去十年间实现了主流应用。回顾过去，我们可以看到，我们曾乘着商业智能应用的浪潮，一路攀升至如今被称为传统数据仓库与商业智能方法及实践的高峰。

然而，几年前，随着组织在评估当前环境和经验教训的同时开始思考其他方法与实践，发展速度有所放缓。行业变革已渗透到数据和商业智能领域，促使人们重新审视现有工具和技术的有效性。结果，一大批新的供应商涌现出来，挥舞着他们的新工具，准备挑战像甲骨文这样的老牌领先厂商。这导致商业——或者更确切地说，商业智能——的常规运作陷入停滞，并让人们有机会重新审视其他选择。具有讽刺意味的是，这种停滞对甲骨文也可能是有益的，因为它得以重新评估和改造其工具集，加入了人工智能和大数据等新组件与技术。

如果我们现在正处于大数据分析时代，这对商业智能究竟意味着什么？我们所熟知的商业智能是否已经消亡？此外，人工智能和机器学习在整个体系中又扮演着什么角色？毫无疑问，新的方法、技术和工具已经改变了商业智能和数据仓库的格局。这些变化的核心，是所谓的现代数据仓库和商业智能，它们采用了新的方法。这些方法被用来实现之前一直宣称的目标，即“在正确的时间将正确的信息传递给正确的人”。这并非背离数据仓库和商业智能的最终目标。

那么，为什么供应商和行业专家声称商业智能已死？也许是因为现在使用的工具有了新的效率和效果。又或者，这仅仅是一种戏剧性的尝试，旨在宣称现状需要改变，是一个夺取行业领导者地位的机会。尽管如此，我们必须正视一个事实：数据科学领域确实出现了必须探索的新概念。正如大数据的概念引发了热议，Hortonworks 在 2014 年 12 月的首次公开募股（IPO）也为新技术和工具带来了新的热潮和合法性。大数据——或者至少是大数据将为企业数据和商业智能及分析带来的承诺——已经到来。

一大批软件公司希望效仿并颠覆传统数据仓库方法，将分析能力推向前端工具的责任范畴——这在很大程度上得益于人工智能和机器学习的辅助。这一战略带来了新的范式和分析的全新方法。或许，这场完美风暴的形态是：海量数据以惊人的速度、以各种格式涌入。我们如何有效应对这股大数据的冲击？

处理大量数据未必是一个新问题。其前身可以清晰地追溯到点击流数据仓库和网络日志分析。那么，现在有何不同？不同之处在于大数据在我们日常生活中的普及，以及为了有效且高效地处理大数据（包括机器学习）而进化或发明的大量新工具和技术。如今，人工智能的新时代预计将成为改变游戏规则的力量，影响我们的日常生活。正如商业智能推动我们利用新技术来使用和管理数据以进行决策和分析一样，人工智能的最新进展正在帮助解决老问题，并引入了处理大数据分析和预测性分析的新方法、新实践和新工具。

事实上，后端供应商已经开始提供硬件解决方案，通过卓越的并行处理和内存计算能力来处理涌入其企业的所有数据。具体到甲骨文，这包括其 Exadata 和 Exalytics 产品。同样，前端的高级分析应用和软件似乎也在进化，以补充后端的能力。

20 世纪 90 年代中期可以被视为这场分析应用革命的起点。当时，新的方法和技术开始与数据仓库和商业智能融合。Informatica 为提取、转换、加载（ETL）成立了一家新公司并开辟了新市场；Cognos 的新技术带来了新的能力，甚至革新了旧有的分析和统计方法；而像 Kimball 的维度建模（用于处理后端数据）这样的方法与实践，为从业者提供了可交付成果的最佳实践。

那是一个实施和开发商业智能解决方案的启蒙时代，人们吸取了经验教训，并开始形成按时、在预算内交付世界级商业智能和分析解决方案的最佳实践。随着人们认识到商业智能和分析不仅仅是一时的技术潮流，而是企业的下一个重大机遇，成功的独立商业智能软件公司成为了寻求战略收购的大型企业软件公司的目标，这些收购有助于它们提供商业智能和分析产品。

大约在 2007 年，顶级软件公司开始制定进入商业智能市场的计划。它们各自收购了合适的公司来完善其产品组合，并提供企业商业智能所需的能力。例如，那一年甲骨文收购了 Hyperion，IBM 收购了 Cognos，SAP 收购了 Business Objects。它们都实现了目标，并在随后的十年里，乘着企业商业智能需求的浪潮，不断改进和完善其产品。

因此，如果说过去十年是许多供应商的改进期，那么这一切在 2012 年左右戛然而止，因为新的方法、工具和技术开始表明，商业智能和分析策略必须根据影响商业智能的新趋势进行革新。这个新趋势过去是、现在也是大数据，它对现状构成了挑战。随着这一新趋势的到来，公司之间涌现出大量的合作伙伴关系，它们寻求合作，以便在新的商业智能和大数据分析格局中提供有竞争力的产品。

我们现在正处于数据科学时代，新的方法被用于提供复杂而有意义的分析以支持决策。越来越多的公司正在建立数据科学部门，并招聘具备特定技能的人才。为了满足这个以数据科学为中心的新环境的要求和需求，必须创建新的高级工具。对于甲骨文公司来说，这体现在 OBIEE 12c 及其可视化分析器上。

## OBIEE 的演进历程：从诞生到当前版本

在数据库和数据管理工具领域，Oracle 堪称“业界霸主”。通过一系列精准的战略收购，Oracle 还凭借其 Oracle BI 工具套件，完善了用于决策支持和分析的下游应用。在过去十年间，Oracle 从几乎没有商业智能产品或服务，到 2007 年通过战略收购成为主要参与者和思想领袖。正如行业分析师所指出的，Oracle 随后经历了爆发式增长，其产品在近十年间占据领先地位，取代了 Cognos 等曾主导商业智能和分析领域的独立供应商。

在 Oracle 收购 Siebel 后，发布了该软件的第一个版本，即 Oracle 商业智能企业版（OBIEE）。第一个主要版本是 10g 版本。然而，尽管 Oracle 的“新”产品备受瞩目，OBIEE 10g 实际上只是收购后立即被重新命名为 Oracle 的 Siebel 产品。仿佛该产品唯一重大的变化就是首页将 Siebel 的 Logo 替换成了 Oracle 的 Logo。在底层，该软件的技术组件并未改变或调整——例如，甚至程序文件的命名方案也清晰可见，表明其源自 Siebel。无论从哪个角度看，OBIEE 仍然是以前被称为 Siebel Analytics 的同一软件程序和软件包。

就其前端和可视化方面而言，它带有“Siebel 风格”。尽管它作为基于浏览器的应用在开发上可能很先进，但许多用户认为它笨重，不一定用户友好或直观。但尽管有这些批评，该软件包作为一个整体是能正常工作的，并提供了端到端的 BI 解决方案。相比之下，其他软件供应商不得不修改和改造其旗舰 BI 产品，从客户端-服务器模式转变为瘦客户端和基于浏览器的模式。作为 BI 行业中“后来者”的 Siebel Systems，能够借鉴经验教训，并在其产品开发中运用最佳实践和最新技术。

因此，正是通过 OBIEE 10g，早期的实践者们聚集在 Oracle 的“新”BI 产品周围，乘着其声望和成功的浪潮，进入了利润丰厚的 BI 和分析市场。这一时期使得新的实践者和实施者能够“初试锋芒”，通过在封闭系统中学习 BI 来积累经验，而无需从头开始构建。结果，该程序在 BI 产品中变得非常流行，用户和实践者们学会了适应现有的软件。我们都屏息以待 Oracle 承诺的改进版整体程序，期待它带来新功能以及程序外观和感觉的改变。

Oracle 迈出了重要的一步，基于从收购的各种软件包中获得的新基础和新套件，创建了一款新的 Oracle BI 产品。这就是 OBIEE 11g，它集成了各种程序，并拥有类似谷歌的前端。这个版本在前端外观和感觉上是一个受欢迎的改进。此外，在 11g 中，整个 BI 套件所有组件的集成也得到了持续改进。用于报表和分析开发的菜单清晰地区分了不同类型的报表和分析。新菜单列出了用于分析的选项（即 10g 中以前的 Answers），主要用于使用 OBIEE 进行即席分析，并单独列出了用于 BI Publisher 的交互式报表（即以前独立的名为 XML Publisher 的产品）。

此外，OBIEE 11g 开始包含与 Oracle 数据集成器（ODI）集成的 ETL 组件，以及与 Essbase 集成的多维数据集组件。OBIEE 首次真正开始感觉并表现得像一个单一的产品。甚至该套件的管理也呈现出全新的外观和企业管理流程。似乎它终于将所有东西整合在一起，以提供商业智能和分析。我们终于到达顶峰了吗？这就是我们所需要的全部吗？这个软件包似乎已经完备，Oracle 的精力现在集中在改进和增强这个基础上。对于传统的数据仓库和商业智能方法，Oracle 凭借其 11g 产品主导了市场，并在多年间作为商业智能和分析领域的顶级领导者占据着主导地位。

但接下来发生的事情改变了一切。该行业经历——并且仍在继续经历——数据处理和分析方式的巨大变革，被称为大数据分析。因此，Oracle 的商业智能产品也响应了这一变化。

2012 年，Oracle 发布了 OBIEE 12c。对于许多实践者来说，这正是我们一直期待的整体 BI 产品。Oracle 最终将所有东西整合成一个面向企业的、有凝聚力的 BI 套件，并包含了用于大数据的数据发现组件。这是软件以及资源和人员的整合，最终创造出了如今真正的 Oracle 商业智能套件。

## OBIEE 机器学习：诞生与历史

常言道，高处不胜寒。所有其他人都扮演着挑战者的角色，试图将你从神坛上拉下来。作为数据库和数据管理系统的领导者，Oracle 准备继续稳坐顶峰，并持续提供基于其关系型数据库管理系统（RDBMS）的以数据为中心的解决方案。想要在它擅长的领域挑战这家领先的数据库供应商，显然是一项艰巨的任务，因为 Oracle 在市场上享有如此主导地位，并且可以说是数据库管理领域的“教科书”。但随后，大数据时代来临了。规则突然改变，游戏的中心不再是关系型数据库。

因此，为商业智能和分析提供解决方案的规则也在被重写。Oracle 似乎陷入了进退两难的境地：它固然可以动用所有资源参与这个新市场，但这样做也可能扼杀自己的主导地位，导致自身的衰落。Oracle BI 的实践者们屏息以待，想看看下一步将把他们这位冠军供应商引向何方。

像 Tableau 或 Qlik 这样的后起之秀和曾经的部门级供应商，则能够利用这一范式转变带来的机遇，填补像 Oracle 这样的大型厂商因反应迟缓、未能及时提供替代方案而留下的空白。最终，随着 OBIEE 12c 的发布，Oracle 似乎承认了那句老话——“打不过，就加入”，为其旗舰产品提供了这个包含大数据组件并融合了机器学习等新技术的重大版本。

行业变革已经渗透到数据和商业智能领域，促使人们重新审视现有工具和技术的有效性。结果，一个全新的供应商领域涌现出来，挥舞着新工具，准备挑战像 Oracle 这样的老牌领先厂商。一切照旧——或者更确切地说，商业智能——停滞了，让人们得以重新审视其他供应商。讽刺的是，尽管 Oracle 可能被视为众矢之的，但这种停滞对 Oracle 也可能是有益的，因为它可以借此重新评估和改造自己的工具集。

如果我们现在身处大数据时代，这对商业智能究竟意味着什么？毫无疑问，新的技术和工具正在被创造出来，旨在在正确的时间将正确的信息传递给正确的人。这是商业智能同样熟悉的目标，它从未改变。但随着一些全球最大、最先进企业的推动，人工智能和机器学习已经进入了企业界。对这些工具和技术的访问已经触及企业的各个层级和组织的各个级别。人工智能和机器学习不再仅仅保留给那些用于战略性事务的最复杂的统计运算。

数据现在无处不在，并且随时可用。曾经非常难以捉摸的数据，如今得益于技术（如互联网）和解决方案（如商业智能和分析）的进步，我们能够访问和利用它们。几十年来，我们一直在努力高效地使用数据系统，但现在现代工具帮助我们自助。每一次新的进步，都引领我们进入了自助式商业智能和数据科学的时代。组织赋能其员工参与其中，让企业各层级都能做出必要的决策，帮助组织在市场中保持竞争力。

但是，当我们谈论自助式商业智能时，必须承认，即使资源和数据可访问，技术和工具也已进步，但深刻的见解和预测性分析并不一定会随之而来。人工智能的应用正在帮助我们以可能尚未完全理解的方式进行预测和规定。因此，通过人工智能提供辅助，可能是对我们工作方式的一种受欢迎的改进。

那么，大数据分析真正的含义是什么？我们认为，解决方案的要素必须解决以下问题：

*   访问大量相关数据
*   性能和处理能力
*   友好的用户界面
*   能够轻松添加新的数据片段
*   数据可视化以产生洞察

具备这些特性，组织就能提供数据分析所需的能力，期望能从那些原本无用或无法提供优势的数据源中获得某种洞察。

但是，即使技术和工具取得了这些进步，用户真的能有效利用这些系统和解决方案吗？毕竟，数据分析不仅仅是关于数据。首先必须对业务有某种程度的理解，才能从原始数据中形成业务洞察。否则，你怎么知道什么样的目标或分析是相关的，并且是向原始数据提出的要求？你怎么知道如何将某些数据片段组合起来形成某种有用的情报？即使是最复杂的系统和解决方案，在不了解业务的情况下也会变得相当无用。此外，考虑到业务解决方案，自助服务可能会产生误导；自助式商业智能的伟大承诺将无法实现——不是因为系统的限制——而是因为个人对业务理解的局限。因此，在当今商业智能领域充斥着声称易于使用的工具和技术的情况下，现在有众多平台声称提供自助式商业智能。

此外，最近由行业对自助服务的变革和需求所推动的更新，增强了 OBIEE 的能力，使其能够链接外部数据（例如来自电子表格的数据），以增强数据仓库中已包含和准备好的数据。最近的进展使得这可以动态地、即时地完成。数据仓库不再孤立存在，不再依赖严格而费力的机制才能作为数据发现和预测性分析的有价值资产被有效利用。确实，像这样允许数据混搭和数据可视化的进步，推动了商业智能的进一步增长，进入了高级分析和有效数据挖掘的领域，也就是现在通常所说的数据科学。

对于商业智能和数据科学的这一新能力，需要为那些有权访问海量、多种类型数据（数据涌入速度之快如同思绪闪现）的用户和实践者提供有效的工具。行业需要能够收集、转换和维护这些数据，同时使用户（甚至是数据科学家）能够以自助服务的方式轻松而强大地自行提供和查询数据。我们提出，行业一直在寻找的自助式商业智能工具——那种能够将成熟的企业数据仓库与用于数据发现的外部数据片段集成在一起的工具——现在已经出现了。

## 作为最佳平台的 Oracle 云上的 OBIEE

自助式商业智能的核心在于，我们能够通过提供交互式且由业务用户驱动的界面来访问底层数据，从而促进基于数据的决策。当今的数据不仅包含结构化数据，还包含非结构化数据。这些数据需要快速处理，并且要求对在线事务处理（OLTP）和在线分析处理（OLAP）采取集成方法，同时还要能从来自各种非结构化来源的数据中发现新信息。因此，用于决策的大数据必须支持新数据、新分析以及新指标，这些指标既涉及历史绩效分析，也涉及预测分析。

这一切的共同驱动力是自助服务，此类分析取决于所询问的内容以及询问的对象，具有敏捷性。业务用户不断变化的需求，完美契合了将 Oracle 云作为访问 Oracle BI 和 Oracle 大数据的最佳平台这一理念。该平台提供数据的实时分析、面向所有类型数据的自助分析，并支持横向扩展采用。交互式数据可视化是一个主要组成部分，可实现对数据的即时自助访问。

自助式分析因这些使能技术而成为现实。诸如移动设备管理、可视化发现和电子表格分析等业务分析流程已由业务用户驱动，通过 Oracle 云，所有必要的数据点之间不再存在脱节。

## OBIEE 中的机器学习

OBIEE 涵盖了当今可用的常见机器学习功能。这并非详尽列表，而是为您提供了一条可轻松融入当前 BI 解决方案的初始路径。常见的机器学习功能包括：

*   BIN 和 WIDTH_BUCKET（监督学习）
*   预测（监督学习）
*   聚类（无监督学习）
*   异常值检测（无监督学习）
*   回归（监督学习）
*   EVALUATE_SCRIPT

OBIEE 12c 内置了四个 R 函数（趋势线、回归、异常值检测和聚类）。此外，12c 还允许您创建和调用自定义 R 脚本。本书将在后续章节中进一步详细介绍这些内容。

## 总结

本章清晰地展示了 Oracle BI 的能力，它不仅能轻松满足即席报告和研究能力的标准需求，还能进一步扩展到高级分析领域。过去，如果没有一定程度的数据库查询技术知识，就无法轻松访问数据。当今的工具和技术为企业界提供了人工智能和机器学习，以发现和提取甚至可能未曾预见的信息和知识。Oracle BI 已将其能力扩展到超越理解您所追求的指标或度量背后业务的需求。相反，现在流程已经反转，您可以从数据中发现有用信息——有时甚至无需任何先验知识或预期——这一切都通过使用人工智能和机器学习来实现。

我们还涉及了大数据和自助式 BI 的概念。随着我们步入一个新时代，大批数据科学家手持 OBIEE 中的自助服务工具，寻求纳入外部数据（甚至是大数据）来增强现有的数据仓库或存储库，以寻找其查询和分析的答案，高级分析以及数据发现的新需求也随之发挥作用。

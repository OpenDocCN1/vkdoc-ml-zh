# 15. 超越 Excel

Excel 是一款出色的商业智能、办公事务及其他众多应用领域的工具。其强大之处源于众多功能，包括公式与函数、自动填充、自动工作簿计算、加载项等。通过自动工作簿计算，对某个单元格中的公式或值所做的任何修改，都会触发所有直接或间接与该单元格相关的其他单元格重新计算，即使它们位于不同的工作表中。重新计算还可以重塑依赖于这些单元格的图表。单元格的值还可以链接到窗体控件，从而实现对数据值和图表的可视化控制。

自动填充功能可自动完成大量单元格的计算，这是一项极其强大的特性。该特性使 Excel 能够处理大规模数据集。Excel 中的数据会自动以表格格式排列，这也使得 Excel 天然适用于许多数据挖掘技术。

Excel 中的数百个函数使其具备了可编程性。我们可以将 Excel 公式视为一条编程语句，将工作表视为模块化函数、类或程序。这些函数可根据其特定用途进行分类，例如财务、数学、统计、查找与引用等。创造性地运用这些函数，为我们提供了通过 Excel 逐步学习数据挖掘的机会。

Excel 的功能一直在不断演进。在我使用的第一个 Excel 版本（`Excel 2003`）中，其可用行数和列数分别为 65,536 和 256。自 `2007` 版本起，可用行数超过 100 万，可用列数超过 16,000。当今 Excel 的容量使其能够处理大型数据集。

Excel 的可用函数数量也一直在增加。表 15-1 列出了自 `2010` 版本以来的新增函数以及自 `2007` 版本以来的函数总数。表 15-1 中的数据来源于 [`https://support.office.com/`](https://support.office.com/)。一般来说，函数集越大，表示能力越强。

我相信，到目前为止，我们已经对数据挖掘有了相当程度的了解，不会再认为数据挖掘或机器学习是一种神秘的技术。我们可能也会问，Excel 还能做什么，因为本书中尚未涉及许多其他数据挖掘方法，例如随机森林、支持向量机、主成分分析、深度学习、自然语言处理（NLP）等。

我想强调的是，本书的目的是通过 Excel 示例介绍基本的数据挖掘方法。我无意在本书中涵盖所有可能的数据挖掘方法，尽管某些其他数据挖掘方法的简化版本也可以通过 Excel 示例进行说明。

我们也必须承认，Excel 不是一种编程语言，也就是说，我们必须承认 Excel 在学习数据挖掘方面的局限性。在上一章中，我提到 Excel 不适合某些文本挖掘任务。在第 `12` 章中，我只能展示如何对大小为 `2` 的项集进行关联分析。当项集大小增加时，不同项集的数量呈指数级增长，通过 Excel 进行关联分析将变得不合适，最终变得不可能。

最初，数据挖掘软件工具提供半自动化的挖掘过程。用户必须一次应用一种数据挖掘方法。为了比较不同方法的性能，用户必须手动尝试不同的方法并比较它们的性能。如今，自动化数据挖掘变得越来越流行。诸如 `RapidMiner` 之类的软件工具提供了“自动模型”，允许用户应用他们选择的尽可能多的挖掘方法，并能自动比较这些方法的性能。一些 `Python` 包，如 `AutoGluon`，甚至可以自动完成 `EDA` 和特征选择过程，生成新特征（例如，对文本数据应用嵌入技术），并构建由一组选定的数据挖掘方法组成的集成机器学习模型。当然，即使 `Azure` 机器学习加载项非常强大，Excel 要提供这样的自动数据挖掘功能也要困难得多。一旦我们通过 Excel 学习了数据挖掘知识，如果我们渴望成为数据挖掘或机器学习专家，我们确实需要熟练掌握数据挖掘软件工具和/或语言。

自动化数据挖掘在挖掘阶段所需的工作量最小，但将大量工作推向了数据准备阶段。如前所述，Excel 可以为用户提供对每个数据准备操作的直接可视化检查。因此，Excel 将始终在数据挖掘实践中发挥重要作用。当数据集过大而 Excel 无法处理时，Excel 仍然可以作为一个很好的工具，在较小规模上测试数据准备过程。

学习是一个循序渐进的过程；它不是，也永远不会是一个自动化的过程。我们知道，边做边学是最好的教育方法。使用 Excel 学习数据挖掘迫使学习者手动经历每一个数据挖掘步骤，为他们提供主动的学习体验。我想说，自动化数据挖掘的趋势使得 Excel 在学习数据挖掘或机器学习方面变得更加重要。

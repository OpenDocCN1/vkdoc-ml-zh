# 2. 判断何时使用智能系统

你有一个想要解决的问题。一个需要优化的现有系统。一个创造新业务的想法。一些你认为客户会喜欢的东西。一个未能产生预期价值的基于机器学习的解决方案。智能系统适合你吗？有时适合，有时不适合。

本章讨论智能系统何时可能是正确的方法，并提供何时其他方法可能更好的指导。它首先描述了可以从智能系统中受益的问题类型。然后讨论了使智能系统发挥作用所需的一些特性。

## 需要智能系统的问题类型

用简单的方法解决问题总是最好的。如果你能在没有智能系统的情况下解决问题，也许就应该这样做。判断是否需要智能系统的一个关键因素是，你认为在系统完善之前需要更新它的频率。如果这个数字很小，那么智能系统可能并不合适。

例如，设想为银行系统的某个部分实现智能。你的“智能”需要在人们取款时更新账户余额。解决方案相当简单：

```
新余额 = 旧余额 - 取款金额
```

类似这样的逻辑（加上一堆错误检查、日志记录和事务管理），并非高深莫测。你可能会遇到一个错误。你可能会遗漏一个错误情况（例如，余额变为负数）。然后你可能需要更新“智能”来修正它。也许需要几次？或者你非常粗心，需要更新十几次才能完成。

智能系统不适合这类问题。它们适用于你认为需要非常频繁地更新系统的问题。数千次、数万次，只要系统存在，每小时都在更新。诸如此类。

有四种情况明显需要这种程度的迭代：

*   **大问题**，需要大量工作才能解决。

*   **开放式问题**，随着时间的推移会持续增长。

*   **随时间变化的问题**，正确答案会随时间改变。

*   **本质上困难的问题**，挑战了我们认为可能的边界。

本节接下来将逐一探讨这些问题。

### 大问题

有些问题规模很大。它们涉及众多需要处理的变量和条件，无法一蹴而就。

例如，网络页面的数量多到一个人穷尽一生也读不完——甚至一百个人也读不完。书籍、电视节目、歌曲、电子游戏、直播流、推文、新闻报道和电商产品如此之多，以至于需要数千人年才能全部体验一遍。

这些问题以及其他类似问题需要大规模处理。如果你想构建一个系统来处理其中某个问题，并希望在部署第一个版本之前就完全完成……那么，你很可能会在尝试过程中破产。

当你遇到一个无法一次性完成的大问题时，智能系统可能是一个很好的起点，也是一种高效推进愿景实现的方式——通过向用户提供他们认为有价值且愿意帮助你改进的东西。

### 开放式问题

有些问题不仅仅是规模大。有些问题是开放式的。也就是说，它们根本没有一个固定的解决方案。它们会持续下去，需要更多的工作，永无止境。网页、书籍、电视节目、歌曲、电子游戏、直播流——每天都有越来越多的内容被创造出来。

试图构建一个系统来推理和组织那些尚未被创造出来的事物，是困难的。

在这些情况下，静态解决方案——即构建、部署然后撒手不管——不太可能奏效。相反，这些情况需要能够长期存在并在其生命周期中不断成长的服务。

如果你的问题有一个有界的解决方案，那么智能系统可能并不合适。但如果你的问题规模大且持续存在，那么智能系统可能是正确的解决方案。

### 随时间变化的问题

事物会变化。有时今天的正确答案明天就错了。例如：

*   设想一个用于识别人脸的系统——然后面部纹身变得超级流行。

*   设想一个用于预测股票价格的系统——然后一架飞机撞上了一栋建筑。

*   设想一个将垃圾邮件移至垃圾文件夹的系统——然后一个天才怪才决定进入垃圾邮件业务并改变了游戏规则。

*   或者设想一个用户难以使用的用户体验——然后他们开始学习如何使用它。

有一件事是确定的——事物总会变化。

变化意味着你昨天实现的智能——对于当时的情况完全正确，让许多用户满意，甚至可能为你的业务赚了很多钱——对于明天将要发生的事情可能完全错误。

应对随时间变化的问题，需要具备检测变化并足够快速地适应以产生意义的能力。

如果你的领域变化缓慢或可预测，那么可能不需要智能系统。另一方面，如果你领域的变化不可预测、剧烈或频繁，那么智能系统可能是适合你的解决方案。

### 固有难题

有些问题天生就难。难到人类几乎无法找到解决方法，至少无法一蹴而就，也无法完美解决。以下是一些难题的例子：

*   理解人类语音。

*   识别图片中的物体。

*   预测未来几分钟以上的天气（显然如此）。

*   在复杂的开放式游戏中与人类竞争。

*   理解文本和视频中人类的情感表达。

在这些情况下，机器学习取得了巨大成功，但这种成功是建立在多年（甚至数十年）的努力之上，包括收集训练数据、理解问题以及开发智能。这类系统仍在不断改进，并且在可预见的未来将持续进步。

解决这类难题的方法有很多。其中一种方法是，如本书所述，利用`智能系统`，在某个有意义的应用中，构建用户与智能创造之间的闭环。

## 智能系统适用的场景

除了需要解决一个足够困难、需要智能系统的问题——即规模庞大、开放、随时间变化、固有难度高，或兼具以上特点——智能系统还需要满足以下几个条件才能成功：

*   问题本身允许部分解决方案，且该方案具有可行性和趣味性。

*   能够从系统使用过程中获取数据，以改进智能。

*   具备影响有意义目标的能力。

*   问题本身值得投入精力构建智能系统。

本节其余部分将依次探讨这些要求。

### 当部分系统可行且有趣时

智能系统本质上总是不完整的，在重要方面存在错误，并且可能犯各种错误。智能系统是否完美并不重要。关键在于，智能系统必须足够好，才能对用户有吸引力（并对你产生价值）。

当一个智能系统做对事情的价值（远）高于做错事情的成本时，它就是可行的。

考虑一个会犯“廉价”错误的智能系统。假设该系统旨在按优化用户在杂货店购物时间的顺序显示购物清单。向右走，拿鸡蛋，再拿牛奶，然后绕到商店后面拿牛排，接着进入下一个过道拿泡菜……如此循环。如果这个系统把一些顺序搞反了，可能会让用户走错方向而浪费时间，比如每次错误浪费 15-20 秒。这很烦人，但并非世界末日。如果错误不太频繁——比如每两次购物才出现一次——那么很容易想象，当系统正在学习全球所有杂货店的布局并适应变化时，用户仍会使用它。

再考虑另一个会犯“昂贵”错误的智能系统。也许它正在控制手术机器人，而错误会危及人类生命。这个系统在可行之前，必须达到高得多的质量标准。也就是说，在将其部署给用户之前，你需要构建一个好得多的部分系统。但即使是这个系统，也无需完美才能可行。记住——外科医生也会犯错。智能系统不必完美（而且大多数永远无法完美），它只需要比其他人做得更好。

关键在于，要变得可行，智能系统必须为用户（以及为你）提供一笔好交易：通过积极成果创造更多价值，同时其消极成果带来的烦恼（和成本）要更少。

### 当你能利用系统数据来改进时

智能系统通过构建使用与智能之间的闭环来运作。当用户使用系统时，智能会变得更好；而当智能变得更好时，系统会为用户创造更多价值。

为了通过使用来改进智能，你需要以谨慎的方式记录用户与系统之间的交互（我们将在后面详细讨论）。在高层面上，这包括捕捉用户看到了什么、他们做了什么，以及结果是积极的还是消极的。并且你需要观察大量、大量的用户交互（问题越难，需要的交互就越多）。这类数据可以通过多种方式用于改进智能，包括机器学习。

### 当系统能与目标交互时

智能系统必须能够改变那些影响目标的事物。这可以通过自动化系统的某个部分，或者向用户呈现有助于他们实现目标的信息或选项来实现。当满足以下条件时，智能系统最为有效：

*   智能系统能够采取的行动直接影响目标。当出现积极结果时，很大程度上应归功于智能系统表现良好；当出现消极结果时，很大程度上应归咎于智能系统表现不佳。影响结果的外部因素越多，构建有效的智能系统就越困难。

*   智能系统能够采取的行动能迅速影响目标。因为行动与结果之间的时间越长，外部因素干扰的可能性就越大。

*   智能系统能够采取的行动与目标保持平衡。也就是说，智能系统能够采取的行动对结果而言足够有意义，以至于通常是可衡量的。

在实践中，确定在哪里部署智能系统，以及尝试用它们解决多少问题，将是关键挑战。目标太大，你将无法将智能系统与之关联；目标太小，则不值得投入所有工作。

事实上，许多大型复杂系统内部有空间容纳不止一个智能系统。例如，一个操作系统可能有一个智能系统来预测将什么放入 `RAM` 缓存，一个来预测用户搜索时显示哪些文件，一个根据使用情况向用户推荐应用，另一个在电脑未插电时管理功耗与性能之间的权衡。

你可以想象用一个单一的智能系统来管理整个操作系统。但这很可能行不通，因为：

*   需要控制的东西太多。

*   控制手段与目标过于抽象。

*   系统获得的反馈类型与智能系统需要做出的决策之间没有足够直接的联系。

### 何时采用智能系统更具成本效益

智能系统在构建计算机系统和服务时，其成本结构与其他方法有所不同。在大多数类似系统中，成本主要由三个部分组成：`智能`、`实现`和`编排`。我们将在本书的第 3、4、5 部分详细讨论这些概念。简而言之，智能是指系统决定“做什么”以及“何时做”的决策方式，即系统的“逻辑”；实现则包括所有实现系统功能、将智能决策结果与用户对接的服务、后端系统和客户端代码；而编排则是在系统整个生命周期内对其进行管理，例如确保系统达成目标以及处理错误。

智能系统的`智能`部分通常比其他方法更便宜，原因如下：

# 智能系统概述

1.  通常，智能系统会自动生成系统的复杂逻辑（而非依赖人工）。当处理庞大、困难或开放式的任务时，智能系统可以大幅节省智能生产的成本。

2.  借助恰当的智能体验，智能系统会在用户与之交互时自动生成训练数据（机器学习所需）。收集训练数据往往是智能创建的主要成本驱动因素，通常需要大量人力投入，因此从用户处获取数据可以极大地改变问题的经济性。

智能系统的`实现`成本与其他基于服务的系统（如网络服务或聊天服务）相似，或略高一些。智能系统与非智能系统的大部分组件是相似的，但智能系统在生命周期编排方面有额外需求，包括创建智能、调整智能体验、管理错误、组织智能等。我们将在本书后续章节详细讨论所有这些内容。

智能系统的`编排`成本与运行非智能服务（如网络服务或聊天服务）相似，但略高一些。智能系统需要持续的工作，包括调整智能向用户呈现的方式、提升智能水平以应对新情况，以及识别和减少错误。

当你读完本书时，你将能够为你的应用准备一份关于使用智能系统效率的详细分析。

## 当你不确定是否需要智能系统时

有时，你可能会遇到用户、数据和智能相互作用的场景，但你不确定是否需要智能系统的所有要素。这可能是出于以下原因：

*   你不确定你的问题是否真的困难，因此不想构建一堆可能用不上的复杂智能。

*   你意识到问题很困难，但不确定构建智能系统的额外工作是否值得你付出努力。

*   你想采取渐进式方法，遇到问题再解决，而不是停下来构建一个智能系统。

这完全没问题。智能系统（如本书所述）并非适合所有人——解决难题的方法有很多。但如果你确实试图解决一个庞大、开放、随时间变化或困难的问题，你最终会遇到本书中描述的许多挑战。即使你选择不按本书描述的方式构建智能系统，本书也能帮助你快速识别常见问题、理解问题本质，并让你准备好用经过验证的方法来应对。

## 总结

智能系统在解决庞大、开放、随时间变化或本质上困难的问题时最为有用。这些问题无法通过单一解决方案解决，并且系统需要随着时间的推移（数月或数年）不断改进。

智能系统在以下情况下效果良好：

*   部分解决方案对用户有吸引力，并能支撑可行的业务，这样你可以从简单开始，逐步提升系统能力。

*   你可以从用户使用系统的过程中获取数据来改进系统。数据通常是构建智能的主要成本之一，因此设计一个能自动生成数据的系统非常有价值。

*   系统能够控制的因素直接影响目标：直接、快速且有意义。也就是说，系统获得的结果可以与智能系统正在执行的操作相关联。

*   当其他方法成本过高，难以规模化时。

在寻找应用智能系统的场景时，将你的问题分解成若干部分。每个部分都应有一个对整体成功至关重要的明确目标、快速直接的反馈，以及能直接影响目标的控制手段（或你的系统可以控制的用户体验）。每个这样的部分都是智能系统的候选应用点。

即使你最终选择完全不使用智能系统，本书中关于实用机器学习、智能与用户体验对接等模式，也几乎会对任何机器学习项目有所裨益。

## 思考题

阅读本章后，你应该了解：

*   你的系统是否能从智能系统中受益。

*   如何在周围世界中找到潜在的智能系统应用场景。

你应该能够回答以下问题：

*   你最喜欢的爱好是什么？它如何能从智能系统中受益？

*   举一个你每天做的常见活动为例，说明为什么智能系统可能不适合它？原因是什么？

思考你最喜欢的一款软件：

*   找出该软件中三个可以使用智能系统的地方。

*   其中哪一个最有可能成功？哪一个最不可能？为什么？

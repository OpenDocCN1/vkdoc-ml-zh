# 16. 智能概述

假设你有一个联网的智能烤面包机，你需要决定它应该烤多久；或者你有一个休息时间应用程序，你需要决定何时给用户休息提示；或者你有一个搞笑的网页应用，你需要决定什么内容有趣。我们将系统中做出这类决策的组件称为“智能”。本书的前面部分帮助你识别何时需要智能，如何通过智能体验将其与用户连接，如何实现它，以及它应该位于何处。本书的这一部分将帮助你创造智能。

智能将上下文映射到关于该上下文的预测。例如，一个智能可能：

* 将网站的使用历史映射到对下周使用量的估计。
* 将一封电子邮件映射到该邮件包含诈骗的概率。
* 将一张图片映射到对图片中黄瓜数量的估计。

本章将更详细地探讨上下文和预测的概念。后续章节将讨论如何创造智能、如何评估它、如何组织它——以及更多内容。

## 一个智能示例

但首先，让我们更详细地看一个智能的例子。想象一个颗粒烤炉。

一个什么？

嗯，颗粒烤炉有点像普通的户外烧烤架，但不同的是，你不需要生起大火，然后等待它达到完美温度，再放上食物，翻来翻去，并希望火候不会因为等待时间过长或过短而太热或太冷……颗粒烤炉有一个装满小木颗粒的料斗，它会根据需要一次一个地将颗粒投入火焰中，以保持完美的烹饪温度。

不可思议。

因此，颗粒烤炉中的智能需要决定何时向火焰中添加颗粒以保持温度。让我们稍微分解一下，探讨这个智能的上下文和预测。

颗粒烤炉的上下文可能包含以下信息：

* 烤炉内的当前温度。
* 1 分钟前烤炉内的温度。
* 过去 5 分钟内添加的木颗粒数量。
* 过去 1 分钟内添加的木颗粒数量。
* 过去 20 秒内添加的木颗粒数量。
* 烤炉外部的空气温度。
* 颗粒中木材的类型。
* 一天中的时间。等等。

这些是可能与保持烤炉处于完美温度这一任务相关的属性。其中一些显然对成功至关重要（如烤炉内的当前温度），而另一些可能有用也可能没用（如一天中的时间）。智能不必使用上下文中的所有信息来做决策——但它可以。

基于上下文中的信息，智能将做出预测。给它一个新的上下文，智能就会预测关于该上下文的某些内容。颗粒烤炉的智能可能尝试预测：

* 未来一分钟内烤炉内部的温度会更高还是更低。
* 未来一分钟内烤炉内部的精确温度是多少。
* 为了维持所需温度，现在是否应该向火焰中添加颗粒的概率。

然后，智能体验将利用这些预测来自动化向火焰添加燃料的过程。如果未来一分钟内火势会太冷——就添加一些燃料。简单！

设计正确的上下文并选择最佳的预测对象是创建有效智能系统的重要组成部分——而要做到正确，通常需要一些迭代和实验。

## 上下文

上下文包括你的智能体可能用于决策的所有计算机可处理信息。智能体可以自由选择使用哪些上下文信息来做出最佳决策。从这个意义上说，上下文是智能体创建者在创建智能体时可以选择的选项调色板。

为了发挥作用，上下文必须满足以下条件：

* 在智能体运行时中实现。
* 可供智能体创建者用于生成和评估智能体。

### 在运行时实现

要使某条信息可供智能体使用，需要有人将其接入智能体运行时。

例如，如果烤炉能知道炉外的温度，它可能会更智能。但要获知炉外温度需要付出努力：需要有人在每台烤炉上安装温度传感器、进行测试、布线、编写驱动程序、轮询传感器，并每隔几秒将其读数复制到智能体运行时中。

常见的上下文形式包括：

* 系统当前状态信息：例如，正在运行哪些其他程序，系统可控制对象的当前状态（灯是开还是关？），以及用户屏幕上显示的内容。使用这类上下文通常很简单，但确实需要实现。
* 用户正在交互的内容属性：例如，歌曲的流派、名称、来源，网页上的文字，以及图片中的像素。这类上下文通常需要处理内容以提取信息，或通过查询来了解更多关于内容的信息（例如在外部数据库中查询歌曲的属性）。
* 用户交互历史：用户过去如何与智能系统交互？要利用这些交互，系统需要监控使用情况、进行汇总并长期持久化存储。
* 用户属性：包括年龄、兴趣、性别。要使用这些属性，系统需要从用户处收集信息并存储。
* 任何相关的传感器读数：这需要将传感器集成到硬件中，并将传感器读数提供给运行时。

决定将哪些内容放入上下文，需要在信息的价值与实现成本之间取得平衡。

一个最佳实践是，首先创建一个包含所有低成本信息的上下文——那些在构建系统时就已经靠近智能体运行时的信息，例如系统当前状态信息，以及用户正在交互的内容属性。

这可能足以起步。但预计随着你追求越来越好的智能体，你需要不断扩充上下文。

在上下文中添加一些推测性的内容也可能很有用。例如，了解烤炉已经开启多长时间可能会有所帮助。也许在烧烤初期，烤炉的金属是冷的，需要更多燃料来加热；也许烧烤一小时后，所有东西都热了，就不需要那么多燃料了。或者，这可能根本不重要。

在上下文中包含此类信息可以帮助你的用户向你展示什么才是重要的。如果该变量与获得良好结果相关，你会在遥测数据中看到它并将其添加到智能体中。如果不相关，你以后随时可以将其从上下文中移除。

### 可用于智能体创建

为了利用上下文创建有效的智能体，需要有人将信息交到智能体创建者手中——很可能以遥测数据的形式。

假设你已经出货了数万台颗粒烤炉。你的智能体在全球运行。在佛罗里达、挪威、津巴布韦，颗粒被添加到火中。烤炉温度上升，烤炉温度下降。你将如何利用所有这些信息来创建更好的智能体？

必须有人收集所有烧烤上下文并将其提供给你。而且上下文需要与结果相关联。例如，想象一下在美国某地的一次烧烤过程。如果颗粒烤炉的智能体运行时知道：

* 烤炉当前温度为 290 度。
* 1 分钟前烤炉温度为 292 度。
* 过去 5 分钟内添加的颗粒数量为 7。
* 过去 1 分钟内添加的颗粒数量为 2。
* 过去 20 秒内添加的颗粒数量为 0。
* 烤炉外部空气温度为 82 度。
* 以及结果：在接下来的一分钟内，烤炉温度升高了 3 度。

并且你从数万次烧烤过程中收集了此类信息，并将其全部反馈给你的智能体创建者——你将能够创造出一些出色的烧烤智能体。

用于创建智能体的数据不一定来自你的用户，但正如我们在关于从经验和遥测获取数据的章节中所讨论的，当数据确实来自实际使用时，智能系统才能发挥最佳效果。

用于创建智能体的数据必须与智能体运行时中存在的数据非常相似。如果它们不同步，智能体在你和你的客户面前的表现就会不同——这可能是一个大问题。

## 智能体可以预测的内容

智能体可以对其遇到的上下文进行预测。这些预测通常是：

* 将上下文分类为少量可能性或结果。
* 对上下文或未来结果的概率估计。
* 根据上下文预测数值的回归。
* 指示哪些实体与上下文最相关的排序。
* 这些类型的混合与组合。

本节将更详细地探讨这些概念。

### 分类

分类是从少量可能性中做出的陈述。它可以是关于上下文的直接陈述，也可以是基于上下文对将要发生的结果的预测。例如：

* 根据上下文，将烤炉分类为：
    * 太热
    * 太冷
    * 刚刚好

* 根据上下文，将电影分类为：
    * 恐怖片
    * 浪漫喜剧
    * 冒险片
    * 纪录片

* 根据上下文，将图片分类为：
    * 一头牛
    * 一个红气球
    * 既不是牛也不是红气球——其他东西

当选择数量较少时（两个、五个、十几个），通常使用分类。

在以下情况下，分类会存在问题：

* 存在大量可能的选择——当你有成百上千种可能性时。在这种情况下，你可能需要将问题分解为多个子问题，或者改变智能体试图回答的问题。
* 你需要知道预测的确定性程度——例如，当你希望在智能体非常确定时才采取行动时。在这种情况下，请考虑使用概率估计而不是分类。

### 概率估计

概率估计用于预测上下文属于某种类型或产生特定结果的可能性。与分类相比，概率估计的结论不那么绝对，但更加精确。分类会说“这是一只猫”；而概率估计则会说“这有 75%的可能性是一只猫”。

概率估计的其他示例如下：

* 该网页有 20%的可能性与政治相关，15%的可能性与购物相关，10%的可能性是诈骗页面，等等。
* 如果我们提议格式化用户的硬盘，他们有 7%的可能性会点击“接受”。
* 下周有 99%的可能性会下雨。

概率估计通常与一个或多个阈值结合使用。例如：

```
if(predictedProbability > 90%)
{
IntelligentExperience->AutomateAnAction();
}
else if(predictedProbability > 50%)
{
IntelligentExperience->PromptTheUser();
}
else
{
// 不执行任何操作...
}
```

从这个意义上说，概率比分类包含更多信息。你可以通过阈值将概率转化为分类，并且可以随时间调整阈值来优化你的智能系统。

大多数机器学习算法在内部都会生成概率（或与概率相似的分数）作为其模型的一部分，因此智能系统使用概率估计而非分类是非常常见的。

在以下情况下，概率估计会存在问题：

* 与分类一样，当存在大量可能结果时，概率的效果不佳。

你需要对微小变化做出反应：上下文的细微变化可能导致概率抖动。通常会对多个连续概率的输出进行平滑处理以减少抖动（但这会增加延迟）。除非你确实非常需要细节，否则对概率进行量化也是一个好做法。

另外请注意，概率通常并非真正的概率。它们更像是方向性指标。数值越高，可能性越大；数值越低，可能性越小。一个智能系统可能预测概率为 90%，但这并不意味着该结果在 10 次中会发生 9 次——除非你仔细校准了你的智能系统。在解读概率时请务必谨慎。

### 回归

回归是对上下文的数值估计，例如：

*   图片中有 6 头牛。
*   本周制造过程将出现 11 个错误。
*   这栋房子将以每平方英尺 743 美元的价格售出。

回归让你能从智能系统中获得更详细的答案。例如，考虑一个用于船只自动驾驶的智能系统。

*   分类可能会说：“正确的方向是向右。”
*   概率可能会说：“你应该向右转的概率是 75%。”
*   回归可能会说：“你需要向右转 130 度。”

这些传达的信息截然不同。三者都说了“向右”，但回归还传达了你需要转很大的角度——你最好赶紧转动方向盘！

在以下情况下，回归会存在问题：

*   你需要对微小变化做出反应：上下文的细微变化可能导致回归结果抖动。通常会对多个连续回归的输出进行平滑处理以减少抖动（但这会增加延迟）。
*   你需要从用户那里获取训练数据：知道“在此上下文中，用户向右转了”比知道“在此上下文中，用户将向右转 114 度”要容易得多。

分类可用于模拟回归。例如，你可以尝试预测具有以下可能性的分类：

*   “向右转 0 - 10 度。”
*   “向右转 11 - 45 度。”
*   “向右转 46 - 90 度。”
*   以此类推。

这会对回归进行量化，并且可能更易于训练和使用。

### 排序

排序用于查找与当前上下文最相关的项目：

*   用户接下来想听哪些歌曲？
*   哪些网页与当前网页最相关？
*   用户想在正在制作的数字剪贴簿中包含哪些图片？

排序已成功应用于数量非常庞大的项目，例如互联网上的每个网页、数字媒体服务中的每部电影或电子商务商店中的每件商品。

当存在许多可能相关的实体，并且你需要找出最相关的少数几个时，通常会使用排序。

排序可以理解为使用概率。针对每个项目，找出它与当前上下文相关的概率，然后根据概率估计值对项目进行“排序”（但实际的排序算法比这更复杂）。

### 混合与组合

大多数智能系统会产生分类、概率估计、回归或排序。但组合和复合答案也是可能的。

例如，你可能需要知道图像中人脸的位置。你可以用一个回归来预测人脸的 X 坐标，用另一个回归来预测 Y 坐标，但这些输出高度相关——正确的 Y 答案取决于你选择的 X，反之亦然。更好的做法是使用一个具有两个同时输出的回归，即人脸的 X 坐标和 Y 坐标。

## 总结

智能是系统中理解用户遇到的上下文，并对上下文及其结果进行预测的部分。

上下文是智能系统可用来做出判断的所有可用信息。智能系统不必使用上下文的所有部分，但它可以使用。

为了作为上下文的一部分被使用，信息需要接入智能系统运行时，并且需要可供智能系统创建者使用。

智能系统运行时和可供智能系统创建者使用的信息必须完全相同。任何差异都可能导致难以发现的问题。

智能系统可以提供多种形式的预测，包括：

*   分类，将上下文映射到少量状态。
*   概率估计，预测上下文处于特定状态或产生特定结果的可能性。
*   回归，根据上下文估计一个数值。
*   排序，查找与当前上下文相关的内容。
*   某种混合或组合，结合了上述一种或多种方法。
